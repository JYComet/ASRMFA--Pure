# 0915ALL Qwen3 全量语料处理设计

## 目标

将以下三棵语料树纳入同一套可恢复、可审计的 Qwen3→时间戳正则化→MFA→后处理流水线：

- `/mnt/Raw/GAMEDATA`
- `/mnt/Raw/v5_0707`
- `/mnt/Raw/Onlinedataset/鸣潮/中文/WutheringWaves2.2_CN/中文 - Chinese`

最终合格 TextGrid 按说话人发布到 `/mnt/Raw/0915ALL/<speaker>/`。过滤结果发布到 `/mnt/Raw/0915ALL/_filtered/<speaker>/`，任务清单、运行收据、过滤原因和统计发布到 `/mnt/Raw/0915ALL/_reports/`。

GAMEDATA 和鸣潮音频在进入主管线前统一首尾静音到 0.5 秒，并按游戏和说话人发布到 `/mnt/Raw/GAMESL/<game>/<speaker>/`。源语料只读。

## 输入规则

### GAMEDATA

- GAMEDATA 的一级目录为游戏名。
- 游戏目录下音频相对路径的第一段为说话人；直接位于游戏目录的音频归入 `_default`。
- 同目录、同 stem 的非空 `.txt` 是权威参考文本。
- 存在权威参考时，Qwen3 只生成时间戳；没有参考时，由 Qwen3 生成文本和时间戳。
- 所有进入任务的音频先做首尾 0.5 秒静音归一化，发布路径为 `GAMESL/<game>/<speaker>/<id>.wav`。

### 鸣潮

- 输入根下一级角色目录为说话人，游戏发布名固定为 `鸣潮`。
- 名为 `其它语音 - Others` 或 `带变量语音 - Placeholder` 的任意子目录及其全部内容从任务中排除，记录原因 `excluded_category`；不修改源目录。
- 同目录、同 stem 的非空 `.lab` 是权威参考文本，并在进入 Qwen3 前按统一文本规则归一化后物化为运行用 `.txt`。
- 所有进入任务的音频先做首尾 0.5 秒静音归一化，发布路径为 `GAMESL/鸣潮/<speaker>/<id>.wav`。

### v5_0707

- 一级目录为说话人。
- 一级目录名含中文字符时排除，但明确保留 `合成ria`。
- `Xuehusang`、`Xiaoyuan`、`Wumi`、`Mieli` 以及 `GS`、`HK`、`SR`、`WW` 前缀按大小写不敏感匹配保留；不含中文字符的其他一级目录也保留。
- 本数据源不执行主管线前的 GAMESL 静音物化。
- 同目录、同 stem 的非空 `.txt` 存在时可作为权威参考；否则走 Qwen3 无参考转写。

## 扁平化与身份映射

扫描阶段为每条音频生成规范身份键：`source_id + game + speaker + NFC(source_relative_path)`。运行 stem 为 `u` 加该身份键 SHA-256 的前 32 个十六进制字符。身份不含音频内容摘要，因此同一源路径内容更新时仍指向同一目标并触发替换；清单另存源音频摘要来识别内容变化。

所有活动分块以运行 stem 扁平化到本地 NVMe。冻结清单保存：来源、游戏、说话人、原始相对路径、原 stem、运行 stem、音频摘要、参考文本路径和摘要、文本模式、静音变换信息、最终发布路径。检测到任何运行 stem 哈希碰撞时任务立即失败，不静默改名。

扁平化避免不同游戏、说话人和数据源之间的同 stem 冲突。最终发布依照冻结清单反向分类。目标目录已有相同运行 stem 时，以临时文件校验完成后执行原子替换；被替换文件及新旧摘要写入运行回滚目录和替换日志。

## 静音预处理

GAMEDATA 和鸣潮音频先转换为单声道 PCM16 WAV，再用当前项目的 RMS 边界检测统一首尾静音到 0.5 秒：不足则补零，超过则裁至目标边界。每条变换记录原始时长、采样率、头尾检测值、时间偏移、输出时长和摘要。

音频先写入私有 staging，完成格式、有限样本、非全静音、首尾静音和摘要验证后，原子发布或替换到 GAMESL。主管线只读取已验证的 GAMESL 文件，确保 Qwen3、MFA 和最终 TextGrid 共用同一音频时间轴。

v5_0707 音频直接进入活动分块，沿用主管线现有音频准备逻辑，不发布到 GAMESL。

## 文本和时间戳合同

- 主管线只允许 `qwen3_hf`，不得加载或回退到 NVASR。
- 参考文本模式：输入文本先执行固定标点归一化，再由 Qwen3 ForcedAligner 生成时间戳。
- 无参考文本模式：由 Qwen3 ASR 生成文本，再由 Qwen3 ForcedAligner 生成时间戳。
- 两种模式都执行同一固定时间戳正则化：前导停顿不转省略号；`sp0` 合并到前词；非前导 `sp1/sp2/sp3` 在原文本边界没有正常标点时变为省略号；正常标点保留。
- 正则化后的基础时间轴进入 MFA 和后处理。后续边界修正只修改工作时间轴；不得用基础时间轴或其他模型结果回退覆盖。
- 最终输出文本来自修复后的最终工作时间轴，并执行已实现的标点和词轨统一规则。

## 分块调度

清单按文本模式和估算音频时长做稳定分块，配置同时限制单块文件数、音频总时长和字节数。活动音频、文本及运行工作区放在 `/mnt/nvme3`，避免 NAS 小文件随机访问成为主瓶颈。

每个 Qwen3 分块使用 8 张 GPU 的常驻独立进程和批量队列。Qwen3 完成一个分块并封存原始时间戳后，GPU 立即处理下一块；上一块同时进入 CPU 时间戳调整、8 路 MFA 分片、英文 MFA 和多进程后处理。调度器最多保留一个 GPU 分块和一个 CPU 分块并行，按实际内存和 NVMe 水位施加背压。

每个阶段写完成收据，记录输入清单摘要、模型身份、配置摘要、完成 stem 和失败 stem。中断后只恢复未完成或收据校验失败的阶段，已经封存的 Qwen3 原始时间戳不可原地覆盖。

## 两条端到端预检

全量运行前自动处理两条固定样本：

1. 鸣潮 `今汐/zh_vo_Chengxiaoshan_main_1_1_145_11`：覆盖 `.lab` 权威参考、文本归一化、0.5 秒静音、GAMESL 时间轴、Qwen3 时间戳、MFA、后处理和说话人发布。
2. v5_0707 `LAria/wavs/LAria_00001`：覆盖无参考 Qwen3 转写、时间戳正则化、MFA、后处理和说话人发布。

预检必须满足：两条均产出五层 TextGrid；音频与所有 tier 时间轴一致；模型收据为 Qwen3；无 NVASR 身份；参考模式文本来自归一化参考；无参考模式文本来自 Qwen3；输出说话人映射正确；无回退、完整性或发布审计错误。任一失败则停止全量。两条均通过后调度器自动进入全量，不再等待人工确认。

GAMEDATA 的 `.txt` 发现、说话人映射、扁平化和静音变换在预检同时执行只读/私有 staging 合同测试，防止该第三种输入布局未被覆盖。

## 输出与守恒

- 合格 TextGrid：`0915ALL/<speaker>/<id>.TextGrid`
- 过滤 TextGrid：`0915ALL/_filtered/<speaker>/<id>.TextGrid`
- 补全音频：`GAMESL/<game>/<speaker>/<id>.wav`
- 报告：`0915ALL/_reports/<run_id>/`

报告包含完整输入、显式排除、无效输入、Qwen3 生产失败、MFA 失败、质量过滤、合格输出和替换记录。以下集合必须无交集且并集等于冻结输入：合格、过滤、输入无效、生产失败。显式排除项单独守恒，不能混入处理分母。

发布以分块为事务：先在私有目录验证 TextGrid/WAV 配对、说话人映射、层级、时间轴、标点投影和摘要，再逐文件原子合并到公开目录。系统性合同错误停止后续发布；单条质量过滤继续运行并记录原因。

## 监控

主调度器输出机器可读状态文件和追加式事件日志，至少包含扫描进度、分块状态、当前阶段、完成/过滤/失败数、8 卡显存和利用率、CPU/MFA 队列、NVMe 使用量、吞吐和预计剩余时间。

执行期间由 Luna medium 只读监控这些收据、日志、进程和 GPU 状态。它不编辑配置、不重启任务、不改变过滤结果；只在预检结论、阶段切换、停滞、可恢复工作进程失败、系统性错误或全量完成时向主任务报告，由主代理执行恢复和最终验收。

## 验收

- 配置和冻结清单准确实现三棵输入规则与两个鸣潮排除目录。
- 0915ALL 启动前为空或已有目标被按替换合同处理。
- 两条端到端预检通过后才开始全量。
- 全量运行期间 8 张 GPU 均由 Qwen3 常驻进程使用，且 CPU 后处理能够与下一 GPU 分块重叠。
- GAMEDATA 和鸣潮的主管线输入与 GAMESL 已验证音频逐条同摘要。
- 所有最终 TextGrid 按说话人分类，时间轴与实际输入音频一致。
- 每个冻结输入都有唯一最终状态；所有过滤和失败都有具体原因。
- 最终报告给出来源、游戏、说话人、文本模式、通过、过滤、失败、替换和排除统计。
